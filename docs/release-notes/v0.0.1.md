# Panko 0.0.1

Panko turns infrastructure code into a self-service API. This first public,
experimental release runs PostgreSQL provisioning through OpenTofu jobs in a
local Kubernetes lab, with a Go CLI and a small browser inspector.

## Try it

Install the CLI using one of these methods:

```sh
brew install hingst-it/tap/panko
```

```sh
mise use -g github:hingst-it/panko@0.0.1
```

```sh
asdf plugin add panko https://github.com/hingst-it/asdf-panko.git
asdf install panko 0.0.1
asdf set -u panko 0.0.1
```

The CLI needs a running Panko gateway. Follow the
[quickstart](https://github.com/hingst-it/panko/blob/v0.0.1/docs/quickstart.md)
to deploy the complete lab and create your first database. The public example
module needs no deploy key or cloud account. An
[AI installation guide](https://github.com/hingst-it/panko/blob/v0.0.1/docs/agent-install.md)
is included for assistants with local terminal access.

## Included

- Database creation, updates, connection details, explicit retry, and safe deletion.
- Validated team-scoped API, dynamically generated OpenAPI, and local bearer tokens.
- Structured status/error codes, provider and module mirrors, and optional egress rules.
- Kubernetes and approved S3 state, migration checks, backup and restore workflows.
- Read-only drift checks, controlled module rollouts, and a sanitized resource graph.
- CLI/admin archives for macOS, Linux, and Windows on AMD64 and ARM64.
- Five Linux AMD64/ARM64 images: `ghcr.io/hingst-it/panko-runner:v0.0.1`,
  `ghcr.io/hingst-it/panko-hook:v0.0.1`, `ghcr.io/hingst-it/panko-gateway:v0.0.1`,
  `ghcr.io/hingst-it/panko-mirror:v0.0.1`, and
  `ghcr.io/hingst-it/panko-module-mirror:v0.0.1`.

Download the archive matching your platform and check it against `SHA256SUMS`.
`panko.rb` is the generated formula for the Homebrew tap. Both `panko --version`
and `panko-admin --version` identify the release. The full list of changes is in
[CHANGELOG.md](https://github.com/hingst-it/panko/blob/v0.0.1/CHANGELOG.md).

## Scope

This is an early release for local evaluation and personal installations, not a
production platform. APIs may change. Database is the only demonstrated resource
type; teams share PostgreSQL administrator credentials. There is no OIDC,
PostgreSQL TLS, high availability, or production-grade tenant isolation.
The lab still deploys through the source checkout and builds local `:dev` images.
Executables do not carry Apple Developer ID or Windows Authenticode signatures;
browser downloads may require explicit approval.

Panko and the example module are licensed under Apache-2.0. Bug reports and
focused contributions are welcome; omit credentials and state from reports.
